Python wins on the merits, and it is not especially close. It wins ten of fifteen dimensions and both the weighted and unweighted average. What follows is why that number does not settle it.

The five that actually decide it

1 · Feed parsing is not a solved problem in JavaScript

This is Python's largest and most underrated advantage. feedparser has twenty years of accumulated handling for feeds that lie about their encoding, omit GUIDs, emit six different date formats, or are simply malformed XML. trafilatura extracts article text better than anything in the JS ecosystem. dateutil parses essentially any date a feed can produce.

On the TypeScript side you get fast-xml-parser, which is a good generic XML parser, and then you write the feed-specific resilience yourself — and rediscover, one broken feed at a time, everything feedparser already knows.

At 514 sources this is not a rounding error. It is probably two to three days of Phase 1 that Python simply hands you.

2 · Free embeddings change the budget

sentence-transformers runs a small embedding model on the same box, at no marginal cost. That deletes both the Vectorize line and the dependency on a metered API.

On a $4.50 VPS the arithmetic comes out ~580 summaries a day against Cloudflare's ~510. On Railway at ~$12 it inverts to ~300, because the convenience is charged for. Where you host Python matters more than the choice of Python.

3 · Nobody patches a Worker

This is Cloudflare's real argument and it is a strong one. No OS updates, no TLS renewal, no process supervision, no disk filling up, no 3am restart. You have already paused this project once. A stack that needs nothing from you is worth more than a scorecard suggests.

Railway removes most of this burden for about $7 a month, which is the honest middle. A VPS does not remove it at all — Docker and CI make it much smaller than it sounds, but "much smaller" is not "zero".

4 · Invocation limits versus a loop

On Workers, collecting 514 feeds means designing around 30 seconds of CPU and 1,000 subrequests per invocation: a tiered scheduler, queue consumers, work sliced across cron ticks. That architecture is already in the plan and it works — but it exists because of the limits, not because the problem needs it.

In Python the collector is an async loop over 514 feeds with a semaphore. That is the whole design.

5 · One language versus two

Cloudflare's genuine win. An Article type is written once and used in the collector, the summarizer and the React component. With Python you generate TypeScript types from FastAPI's OpenAPI schema in CI — which works well, but it is a bridge that can drift, and it is one more thing in the pipeline.

For a solo project maintained in evenings, one language is worth more than it looks on paper.

The verdict

Take Cloudflare if you want to stop thinking about it

Lower score, better fit for the actual situation. One language, zero operations, half a day to first deploy, and a plan already written against it. You paused this project once over $5 — the version that survives is the one that asks nothing of you when you are busy. This remains my recommendation.

Take Python on a VPS if the pipeline is the interesting part

Better tools for exactly this problem, more summaries per rupee, no invocation limits, portable, and the most conventional CI/CD of anything here. The price is a box you own and a second language. If ingesting 514 messy feeds sounds like the fun bit rather than the chore, this is the better build.

Or split them — Python pipeline, Cloudflare edge

Python and Postgres on a VPS do the collecting, clustering and summarizing, where Python is genuinely better. The React front end deploys to Cloudflare and caches the composed page at the edge, where Cloudflare is genuinely better. Roughly $10 a month, both advantages, at the cost of two deployment targets instead of one.

What would change my mind

Toward Python: if you already write Python daily · if you want real ML on clustering later · if the archive matters in five years · if lock-in bothers you.

Toward Cloudflare: if this must run untouched for months · if evenings are scarce · if global latency matters because you will share it · if a second language sounds like friction rather than fun.
