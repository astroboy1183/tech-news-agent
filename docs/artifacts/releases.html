How releases work

Branchingmain is always deployable. Work on feat/* or fix/*, open a PR, squash-merge.
DeployEvery merge to main deploys to production automatically. No separate staging — a Worker version rolls back in seconds.
Tagginggit tag v0.3.0 && git push --tags triggers build, migrate, deploy, then publishes the GitHub Release.
NotesGenerated from Conventional Commits since the previous tag, then edited by hand before publishing.
Rollbackwrangler rollback reverts in seconds. D1 migrations are forward-only, so every migration must be additive.

Commit convention. feat: fix: perf: refactor: docs: test: chore:, scoped by area — feat(collect): add WebSub subscriber. This is what makes generated release notes readable.

The ten releases

v0.1 through v0.5 ship as GitHub pre-releases: the pipeline works but there is nothing to look at. They still deploy to production, because a working pipeline with no UI is exactly what those phases are for.

v0.1.0FoundationPRE-RELEASE~0.5 day
  • React Router v7 on Workers with scheduled and queue wired alongside fetch — the integration proved before anything is built on it
  • D1 with the full migration, including articles_fts and its triggers
  • KV, R2, both queues, Vectorize index
  • GET /health reporting every binding; ~200 seed sources
Ship when/health green in production and CI deploying on merge.
v0.2.0CollectorPRE-RELEASE~4 days
  • Tiered scheduler, conditional GET, WebSub push
  • RSS, Atom and JSON Feed with adapters for HN, Reddit, GitHub and arXiv
  • URL canonicalization, dedupe, headline normalisation, rule-based classification
  • /raw — the reality check, and the headline census committed to the repo
Ship when24 hours unattended yields ~7,900 rows, and re-running adds zero.
v0.3.0ClustersPRE-RELEASE~2 days
  • Trigram candidates, embeddings only for the ambiguous cases
  • Cluster records with arrival timelines
  • Corroboration and velocity scoring
Ship whenClusters average >1.8 members and 30 spot-checks show no false merges.
v0.4.0SummariesPRE-RELEASE~2.5 days
  • Per-section budget allocation with floors
  • Cluster-level summarization through the Batch API
  • KV spend ledger with a hard daily cap; prompt caching verified
Ship whenA full week stays under $0.45/day with every section clearing its floor.
v0.5.0Editorial enginePRE-RELEASE~2.5 days
