What actually decides this

Every option below can build the portal. They differ on four things, and only four:

QuestionWhy it matters here
Who owns uptime?Serverless means nobody patches anything. A VPS is cheaper and you are the sysadmin.
How much is left for AI?Hosting and summaries compete for the same $20. Every dollar of hosting is ~37 fewer summaries a day.
Does the archive outgrow it?~7,900 articles a day is 2.9M rows a year. SQLite has a ceiling; Postgres effectively does not.
Invocation limits, or a process?Serverless means CPU budgets and timeouts to design around. A persistent process removes that entire class of problem.

Frontend is settled either way: React Router v7, server-rendered then hydrated, runs on every option here.

The eleven stacks

A

All-Cloudflare

~$20/mo
Workers · D1 + FTS5 · KV · R2 · Queues · Vectorize · Workers AI · Access  +  React Router v7 · Claude Haiku
For
  • One platform, one bill, one dashboard — nothing to wire between vendors
  • No servers, no patching, no uptime to own
  • Edge-rendered globally; cron, queues and vectors all native
  • Cheapest path that meets every requirement — leaves $13.50 for AI
Against
  • D1 caps at 10 GB per database — about three years at this volume
  • SQLite FTS5 is good, not Postgres-good
  • Deepest vendor lock-in of any option here
  • Vectorize is younger than pgvector
Recommended. The only option where the whole $20 budget survives, and the pieces the portal grew into — image caching, backups, vectors — are all native rather than bolted on.
B

Cloudflare + Neon Postgres

~$25–40/mo
Workers · Neon Postgres + pgvector + tsvector · Hyperdrive · KV · R2 · Queues  +  React Router v7 · Claude Haiku
For
  • Real Postgres: proper full-text, window functions, no storage ceiling
  • pgvector replaces Vectorize — one store for rows and vectors
  • Neon branches give you a real staging database
  • Portable — Postgres runs anywhere if you ever leave
Against
  • Two vendors and connection pooling to reason about
  • Neon's free tier is 0.5 GB; the paid tier eats most of the AI budget
  • Extra network hop from Worker to database
  • More moving parts for a one-person project
The upgrade path. Right if the archive matters long-term or search quality is the point. Take it when D1's ceiling actually bites, not before.
C

Vercel + Neon + Upstash

~$40–60/mo
Next.js or RRv7 on Vercel · Neon Postgres · Upstash QStash + Redis · Vercel Blob  +  Claude Haiku
For
  • Best-in-class developer experience and preview deployments
  • React Router and Next both first-class
  • Huge ecosystem and documentation
Against
  • Vercel Pro is ~$20/mo before anything else runs
  • Cron granularity is worse than Workers; Hobby is once-daily
  • Three vendors minimum, four with AI
  • Function timeouts make long collection runs awkward
Great for a product with a team and a budget. For a solo $20/mo portal it spends most of the money on hosting rather than on summaries.
D

Railway — one PaaS

~$10–25/mo
Node or Bun service · Railway Postgres + pgvector · Railway Redis · Volume storage  +  React Router v7 · Claude Haiku
For
  • Persistent process — real cron, real background workers, no invocation limits
  • Long-running jobs are trivial; no 30-second ceilings anywhere
  • One dashboard, one bill, genuinely simple
  • Postgres and Redis provisioned in a click
Against
  • Not edge — a single region, so latency varies by where you are
  • Usage-based billing can drift upward as volume grows
  • You still own the app process and its memory
The best non-serverless option. If fighting invocation limits and CPU budgets sounds tedious, this removes that entire class of problem for roughly the same money.
E

Fly.io

~$10–25/mo
Bun or Node on Fly Machines · Fly Postgres + pgvector · Upstash Redis · Tigris object storage  +  React Router v7
For
  • Real machines that can scale to zero, placed near you
  • Postgres in the same private network — very low latency
  • Full control over the runtime and process model
Against
  • You own Postgres backups and failover unless you pay for managed
  • More operational surface than Railway for the same shape of app
  • Machine sizing and scaling are yours to tune
A better fit than Railway if you want multi-region or plan to outgrow one box. More knobs than this project needs today.
F

VPS + Docker Compose

~$5–8/mo
Hetzner CX22 or DO droplet · Node/Bun · Postgres + pgvector · Redis · Caddy · Docker Compose  +  React Router v7
For
  • Cheapest compute by a distance — €4/mo buys more than any serverless tier
  • No platform limits at all: parse what you like, run what you like
  • Everything in one place, easy to reason about
  • pgvector, Meilisearch, anything you want to add is just another container
Against
  • You own uptime, patching, TLS renewal, backups and monitoring
  • One box is one point of failure
  • No edge distribution
  • The hours you spend on ops are hours not spent on the portal
Objectively the most capability per rupee. The question is whether you want to be the sysadmin — a news portal that dies because a disk filled up is worse than one that costs $15 more.
G

Supabase-centric

~$25–35/mo
Supabase Postgres + pgvector + pg_cron + Storage + Auth · Edge Functions  +  RRv7 on Cloudflare Pages · Claude Haiku
For
  • Batteries included: database, auth, storage, realtime and cron in one product
  • pgvector and full-text native; excellent dashboard and SQL editor
  • Row-level security if the portal ever gets multiple users
  • pg_cron means scheduling lives next to the data
Against
  • Edge Functions are less suited to heavy, long collection runs
  • Free tier pauses after a week of inactivity; Pro is $25/mo
  • You'd likely still host the frontend elsewhere
Strong if you expect real user accounts later. The auth and RLS story is the best here by some margin.
H

Deno Deploy

~$0–20/mo
Deno · Deno KV · Deno Cron · Deno Queues  +  Fresh or RRv7 · Claude Haiku
For
  • Generous free tier; cron, KV and queues are built into the runtime
  • TypeScript-native with no build step
  • Genuinely simple deployment model
Against
  • Deno KV is key-value, not relational — awkward for clusters and joins
  • You would need an external Postgres for anything relational
  • Smaller ecosystem than Node or Workers
Elegant for small services. The data model here is relational enough that KV-only becomes a fight.
I

Python stack

~$10–25/mo
FastAPI · Postgres + pgvector · Celery + Redis · on Railway, Fly or a VPS  +  React Router v7 frontend
For
  • Best ecosystem for this exact problem — feedparser, trafilatura, readability, dateutil
  • sentence-transformers runs embeddings locally for free — removes the Vectorize line entirely
  • Celery is a mature, honest background-job system
  • If you ever want real ML on top, you are already there
Against
  • Two languages in one project — Python backend, TypeScript frontend
  • Not serverless; you own a process and its deployment
  • Slower to first response than Workers, though irrelevant here
The dark horse. Python's feed and text-extraction libraries are markedly better than anything in the JS ecosystem, and free local embeddings genuinely change the budget. Costs you language uniformity.
J

Oracle Cloud Always Free

$0 infra + AI
Oracle ARM VM — 4 cores, 24 GB RAM · Docker Compose · Postgres + pgvector · Caddy  +  React Router v7
For
  • Genuinely free forever — 4 ARM cores and 24 GB RAM, no trial clock
  • Vastly more compute than any paid tier discussed here
  • Whole $20 goes to AI, roughly tripling summary coverage
Against
  • Oracle reclaims idle Always Free instances with little warning
  • Account approval is notoriously unreliable
  • All the VPS ops burden, with a vendor that owes you nothing
  • No SLA of any kind
Unbeatable on paper. The risk is real though: a portal that vanishes because Oracle reclaimed the instance is a bad trade for $5/mo.
K

AWS serverless

~$15–40/mo
Lambda · Aurora Serverless or DynamoDB · SQS · S3 · EventBridge · OpenSearch  +  RRv7 on CloudFront
For
  • Scales further than this project will ever need
  • Every component is mature and battle-tested
  • Skills transfer to most employers
Against
  • Most complex option by a wide margin — IAM, VPC, cold starts
  • Cost is genuinely hard to predict at small scale
  • OpenSearch alone can cost more than the entire budget
Right answer at a thousand times this scale. At this one, the complexity tax is not repaid.

If you want one answer

Recommendation

A — All-Cloudflare, with React Router v7. It is the only stack where the whole $20 survives to become summaries, and every piece the portal grew into is native rather than bolted on. The plan is already written against it, so it starts today.

D — Railway is the one I would pick instead if invocation limits and CPU budgets sound like a fight you would rather not have. A persistent process makes the collector trivially simple, for roughly the same money.

I — Python deserves a real look if you are comfortable with two languages. Its feed and text-extraction libraries are genuinely better, and free local embeddings would meaningfully increase how many stories get summarized.

Everything except the runtime is reversible later. The database is the one choice that is expensive to change, which is the only reason D1's ceiling is worth thinking about now rather than in year three.
